## MAJOR DECISION: NAV MODEL PIVOT — D-PAD-ONLY → RING NAVIGATION

**S97 brainstorm gate replaced the S96 D-pad-only ruling with the ring-navigation model from `C:\Users\danie\Downloads\files\S94_GAMEPAD_RING_NAVIGATION_SPEC.md` (dated April 16, 2026).**

### Timeline
- S91–S96: Stack model shipped (~950 LOC). A=confirm, B=pop/shade, D-pad=tab cycle at root + cone nav in panel. Required button presses to traverse depth.
- S96 closeout (April 15): Design director locked "D-pad-only" direction. D-pad right = deeper, left = back, A = interact only, B = hard close, Y = lifecycle.
- S97 brainstorm (April 16): User supplied Downloads S94 ring spec. Direction pivoted to ring navigation instead.

### Current model (ring — locked, implemented S97 core)
- **LB / RB** = cycle focusable zones in the window's flat `_focusRing` (skip non-focusable, wrap)
- **D-pad** = spatial nav WITHIN the current zone ONLY (cone algorithm, 90°, 2× off-axis weight, no-wrap)
- **A** = `onActivate` — zone-dependent action (switch tab, toggle drawer, activate item, etc.)
- **X** = `onContextMenu` — open ZeD_ContextMenu on focused element
- **Right stick |v|² > 0.81** = instant windowshade + release focus (aiming escape)
- **B tap** = shade all registered windows; **B hold (>=400ms)** = close all (hard close)
- **Y tap** = open both (no focus) / cycle Char↔World (both open); **Y hold** = toggle windowshade lock
- **BumperChord** (zoom chord) disabled while a ZeD window is focused; bumpers reclaim UI role; re-enabled on release

### Philosophy
Flat > nested. Zone cycle = one button press. D-pad always means "move inside this zone". No mode switches, no depth counters, no "pop to root."

### S98 scope
Wire `_focusRing` into Character and World windows per `GAMEPAD_AUDIT.md` ring-zone proposal. Delete legacy stack-API call sites. Full AC-F1..F11 live QA sweep. Reconcile GAMEPAD_SPEC.md to ring model.
