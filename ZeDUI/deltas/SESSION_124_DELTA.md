# Session 124 delta — true UI scaling (Oct 13 2026)

Director brief: "ui scale next. BUT, I want true scaling. Adaptive to the resolution so really doesn't need to be adjusted. The font option is extra. The dream is everything scales not just the text." Approved: 1080p base, phase 1.

## Probes (live, stable 42.20.2, 3840x2160 rig) — Q138–Q140

- `ISUIElement:drawTextZoomed(str, x, y, zoom, r, g, b, a, font)` scales text continuously; `MeasureStringX * zoom` is the exact drawn width (underline rects matched at 1x / 1.37x / 2x / 2.5x / 3x). Bitmap atlases blur past ~1.4x.
- Distance-field text: `media/fonts/EN/fonts.txt` entries take `type = sdf` on ANY slot; shader `media/shaders/sdf.frag` thresholds alpha at 0.5. The engine's own SDF faces (Open Sans) zoomed 3x-4x stayed crisp. Vanilla atlases: BMFont, face size 32, padding 4, spacing -8, 512x512 pages numbered from 1.
- The engine font-size option (16px / 19px / 26px / 33px / 38px / "Scale with window height") does not change ZeD's bitmap slots - at option 2 the live `Small` slot measures the 1x face. It becomes the user's taste multiplier.
- `TakeFullScreenshot` writes an all-white frame while the fullscreen window is minimized (321,575-byte PNG).
- A browser-embedding route (the Fallout 4 HTML UI) has no equivalent here: no native plugin path for mods. The in-engine equivalent is one root scale in design units (CSS `rem`).

## Phase 1 — root scale + text engine

- `shared/ZeD/Scale.lua`: `ZeD.Scale.root()` = clamp(screenHeight / 1080, 0.75, 4) x user multiplier (`USER_MUL` by font option: 0.85 / 0.92 / 1.0 / 1.15 / 1.3 / 1.0), cached, refreshed every 30 ticks and on `OnResolutionChange`; `ZeD.Scale.px(units)`; `ZeD.Scale.override` for QA. `ZeD.Text.width / height / draw` wrap the zoom path and accept the rich font entries.
- `ZeD_Dashboard` / `ZeD_Watch`: `_scale()` reads the root scale (the text-size preset no longer multiplies in); `_text` draws through `drawTextZoomed` at the organism scale so glyphs follow the plates; `_measure` returns base units.

- Verification plan: forced root scale 1.0 / 1.333 / 2.0 captures of the sports-car dash + watch; then the same with SDF fonts after a restart (fonts load at boot).

### Fluid card built (Oct 13, mockup `ZeDUI/mockups/zed_fluids_v1.html`; director: "go with your recommendations, build it")
- **Surface:** a new object-card kind (`ObjectCardFluid.lua`) in the World window card drawer. Header: the FROM container's name, its icon, and a pill with the liquid (its own colour dot) or a red TAINTED. Verbs POUR (primary), SWITCH, EMPTY. Body: two vessel boxes (POURING FROM / POURING TO, vanilla's words) with vertical tanks in each liquid's colour, ticks at quarters, a white line where the level ends up, light hatching on what leaves and the incoming liquid hatched on top of the target; between them the liquid's name, the arrow, the amount (distance-field digits) and MAX POUR. AMOUNT row: catalog slider (drag, or D-pad left / right in 5% steps) with 1/4, 1/2, ALL; it starts at the most that can pour. LIQUIDS: each liquid with a bar, litres and share; TAINTED tag where vanilla's tooltip would show it; the poison level only in debug, as vanilla. YOUR CONTAINERS: the world container the card opened on (pinned, with its distance) and every liquid container you carry (bags included), each with a gauge, a tag (EMPTY, SAME, MIXES, FULL, WON'T MIX, WON'T TAKE, TOO HEAVY) and FROM / INTO.
- **Pouring:** POUR brings carried items to the main inventory, walks to a world container (vanilla's `ISFluidUtil.doWalkTo`), then queues `ISFluidTransferAction` with copies of both containers, as vanilla's window does. While it runs, a POURING band shows the litres moved with STOP; the verbs and the list lock. EMPTY confirms in the footer ("Pour 2.50 L of mixture out on the ground?") and uses vanilla's empty (item or world).
- **Hooks** (`Overrides/Fluids.lua`): `ISFluidContainerMenu.showUI` and `ISWorldObjectContextMenu.onFluidTransfer / onFluidInfo` open the card at once (no walk, no 10-tick panel action); `ISFluidTransferUI.OpenPanel` and `ISFluidInfoUI.OpenPanel` catch every other caller. Container Info is the same card with nothing in POURING TO; the controller lands on the first INTO that takes the liquid.
- **Card core additions** (`ObjectCards.lua`): the leash applies only to cards about a tile (a pour between your own bottles has none); zones can `drag` (slider) and take D-pad left / right (`dpad`); a kind can choose the opening focus (`openFocus`); the pill can carry its own dot colour; opening holds focus on the back button for one frame so the previous card's row never scrolls the new one.
