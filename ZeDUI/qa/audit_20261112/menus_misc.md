# QA script audit: menus, options, mods, console, guide, messages, balloons, languages, everything else

Read-only audit, Nov 12 2026. Sources: `ZeDUI/tools/qa/` (scripts, manifests, runners), `ZeDUI/qa/regression/*.md`
(1,018 run reports, parsed for every script row), `ZeDUI/qa/` CHECK / QA / HANDOFF files, `ZeDUI/PUNCH_LIST.md`, and
`git log` per script (history was rewritten Nov 9, so commit counts are a floor, not exact).

How to read the numbers:
- **Results** are taken from every regression report since Nov 5 (or all-time where noted "all"). P/W/F/T/S = pass,
  warn, fail, timeout, skipped. "Skipped" is nearly always a run that stopped earlier, not this script.
- **Time** is the average seconds the script itself ran. Main-menu scripts also cost a full game launch and quit each
  (about 1.5 to 2 minutes) on top, and their runners never write a report, so they have **no recorded results at all**.
- **Repairs** = commits that touched the script (plus punch-list "test side" notes where they exist).

## The short version

1. Almost nothing in this area fails because of where it is staged. Menus, options, the console, the guide,
   messages and languages don't need a place in the world, and the drag strip (925,13040) is a fine neutral spot for
   them. The "animals off a farm, cars in the woods" problem belongs to other areas.
2. The waste here is different, and it has three sources: (a) scripts that **check nothing** (they only print numbers
   or take pictures nobody compares, so they always "pass"); (b) **in-game copies of logic a sim already proves** outside the game;
   (c) **one-off scripts** written for a single punch-list item or beta, still sitting in the folder and in about 150 one-off
   `batch_*.ps1` / `b*_run.ps1` runners.
3. Real fails in this area were mostly the test's own: timing (b11_notes, dual_pin, two_widths), the real-mouse
   helper (release_check, b9a_8), or the wrong mod set on (files_game, messages in mod runs). The one real mod bug
   the area's scripts caught recently is the Chinese balloon (158), and it was found by a by-hand probe, not by a script.

## Worst offenders

1. **zedqa_soak**: 10 to 13 minutes in every full regression, about a fifth of the whole run, with no pass/fail at all.
   It logs a trend line nobody reads; it has never failed in 68 runs. Cut it to two rounds with a real
   "elements before = after" check, and run the long version once per release.
2. **zedqa_b11_notes**: failed every single run since it was written, at both sizes, and was copied to _r2 and _r3 and
   run three times in one manifest with the same three fails. Punch list 165 already says the fails are the test's
   (it reads before the window shows, and it never scrolls the row into view). That is the "running loops fixing a
   test" pattern. Take it out of the regression.
3. **Real-mouse scripts** (release_check step 3, b9a_8, dual_pin's away waits): the desktop-mouse helper is the cause
   of most of their FAILs and WARNs. b9a_8 never passed (0 of 6). Where a sim exists (dual_pin, window_saved_pos), use
   the sim; where the real mouse is the point (release check), report a helper miss as "not run", not as a mod fail.
4. **Scripts that can't fail**: testlang (32 pictures, no checks, 100+ s), scalewalk, win, rootchange, tm,
   button_case_game. They only fail on a crash, so they cost time but don't catch layout bugs. Merge the scale ones into uiscale
   with real checks; drop testlang from the regression; button case is a string rule a sim can check.
5. **In-game copies of sims**: the four console scripts, guide_bubble, guide_ads, ctx_overlap, dual_pin,
   window_saved_pos, files_game, sc_font. Each has a sim that loads the same real files and runs in seconds without the
   game. The in-game version adds a launch, timing waits, and a chance to fail on setup (files_game failed only
   because other mods were on).
6. **zedqa_158_balloon / zedqa_sc_font in English**: the Chinese bug only happens with the game in Chinese, and the
   regression runs in English, so both pass whether the bug is there or not. sc_font passed the whole time 158 was
   live. The logic belongs in balloon_cjk_sim; a person checks the look once in Chinese.
7. **Clutter**: about 120 in-game scripts in this area, most written for a single punch-list item or beta (menu_*,
   mods_*, book83_*, guide82_*, b8_*, b8a_*, b9a_*), plus about 150 one-off `batch_*.ps1` / `b*_run.ps1` runners. Main-menu
   scripts write no report, so nothing records whether they ever passed. They are not run, but they make "what is the
   test suite" hard to answer. Move the done ones to an archive folder.

Net effect if the verdicts are taken: the regression loses about 15 to 17 minutes from this area (soak, testlang,
scalewalk, b11_notes, guide_bubble, ctx_overlap, tm, sc_font, 158_balloon, segbars), and no coverage is lost. What
it removed is either covered by a sim or never checked anything.
