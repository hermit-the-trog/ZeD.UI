# Performance pass 2 (Oct 29 2026)

A fresh profile of the code after 0.2.0-t10 (the cohesion pass, the pixel icons, the window menu and help line had never been measured), then one fix. Fullscreen 3840x2160, ZeD scale 1.75x, -debug, game 42.22, the ZeD-QA save's stocked character (every menu full, 64 items in the main inventory) at the Irvington drag strip. Frame cap 120 Hz (vsync), so a scene's average frame time of about 8.4 ms means "at the cap"; the Lua costs are the measure.

Script: `ZeDUI/tools/qa/perf_now.lua` (new: no staged gallery scene needed; manifest `zedqa_prelude.lua | pre`, `perf_now.lua | pnow | timeout=900`). Per scene it records the frame time with nothing wrapped, then the costliest elements (a timer on every prerender / render on the window trees; the HUD scene on every top-level element the game holds), then a draw-call census (ZeD's lean draw calls and ISUIElement's counted apart, ZeD.TM's measures too). Reports: before `qa/regression/2026-10-29_0943_fullscreen4k.md`, after `..._1008_...`.

The Oct 22 leads are closed: the belt is 0.29 ms (was 2.63, then 0.72), the window frame and overlay about 0.23 ms a window, the HUD 0.7 ms in all. The inventory list (1.6 ms, the Character window's 64 rows) is the next biggest and is the file another session is changing today (the stack weight), so it was left alone.

The Skills tab was the one scene over the cap: 923 rectangles, 136 borders, 159 texts and 262 measures a frame. The training-materials section draws one status square per book per skill (the stocked character has most of them) and the grid draws every skill row, all of it every frame whether or not it is inside the scroll view (the stencil clipped it, after the Lua had paid for it), and each training row re-ran the truncation's binary search (up to eight measures).

## The fix (SkillsTab.lua)

- Rows wholly above or below the scroll view are laid out but not drawn (the grid's rows and the training rows and their unfolded book rows). The stencil drew nothing of them before, so the pixels are the same. Hit zones, hover and the controller's mark are unchanged (the mark is only asked of the focused row).
- The truncated label is kept per font, room and string (dropped with the token table or the root scale, as ZeD.TM drops its own).
- The row font's height is measured once (bodyH), not per row.
