# Mod folders, separators and load order: map for the gamut sweep (QA, Nov 27 2026)

A read-only map of four surfaces of ZeD's mod manager at the main menu (the Mods screen): the folders on the Mods list, the separators on the Load order page, the Load order page itself (pins, rules, Find, Auto, Undo, Done) and the Map order page, against the game's own screens for the same jobs (B42: ModLoadOrderPanel and its list, MapOrderUI and its list, the model's save path). The main mod list, the detail panes, profiles and safety are mapped elsewhere; they show here only where these pages call them. Line refs are as read on Nov 27. Nothing was run.

**Where it lives.** All four are pages or layers of one window, ZeD_MMMods (MM). Folders extend the Mods list by wrapping its methods (MF:64-70, 1045-1245); separators wrap the Load order page (SP:134-138, 849-954, 1103-1108); the Load order and Map order pages are OP. The window's page field is "list", "order" or "maps" (MM:104). The models that draw nothing are FD (ModFolders.cfg) and OR (the order rules and the profile file).

Short names: MF ZeD_MainMenuModsFolders.lua, SP ZeD_MainMenuModsSeps.lua, OP ZeD_MainMenuModsOrder.lua, FD ZeD_ModFolders.lua, OR ZeD_ModOrder.lua, MM ZeD_MainMenuMods.lua, ST Settings.lua, SM SafeMode.lua, TK shared/ZeD/Tokens.lua, ZUI shared/Translate/EN/UI.json (ZeD's words). QF ZeDUI/tools/qa/zedqa_mods_folders.lua, QO ZeDUI/tools/qa/zedqa_mods_order.lua (the existing scripts).
The game's files (media/lua/client/OptionScreens/): MLOP ModSelector/ModLoadOrderPanel.lua, MOLB ModSelector/ModOrderListBox.lua, MOUI ModSelector/MapOrderUI.lua, MPLB ModSelector/MapOrderListBox.lua, MSM ModSelector/ModSelectorModel.lua, MSEL ModSelector/ModSelector.lua, MAPS MapsOrder.lua.

## 1. What it does

**Getting there:**
- The Mods screen's band (MM:1240-1275): New folder... (MF:765-769; not on the Workshop tab, not in Lite, MM:1253), Profiles and Load order (MM:1259-1261), Map order only while two map mods share cells (MM:1263; the clash test is cached for a second, MM:220, 1240-1245).
- The first folder can also come from a mod row's menu (right-click, Shift+F10 or the menu key): Move to folder, New folder... (MF:1110-1117, 598-618). Once any folder exists the Mods list is grouped (MF:73-76, MM:1411-1412).
- Separators live on the Load order page only (SP:75): the band's New separator..., a mod row's menu, a separator's menu (SP:1096, 1169-1176, 1208).
- The list being edited follows whoever opened the Mods screen: the main menu, a new game, a save's own list or a server's settings (OR:236-246). Pins, rules and separators are kept per list under "@list ..." sections.

**Data and files (all under %USERPROFILE%\Zomboid):**
- **Lua\ModFolders.cfg**, the file of the [B42]Mod Folders mod (Workshop 3779201168), in its own format (FD:3-21): version=2, next=<n> (never reused), folder=<id>|<1 open, 0 closed>|<name as hex UTF-16 units>, member=<mod id as hex>|<folder id> (the last line for a mod wins). A line ZeD does not change is written back as read; lines it can't read stay in place (FD:7-10, 160-162, 171-187). A version 1 file (%-escapes) is read as the mod reads it and rewritten as version 2 on the first change (FD:57-97, 318-323). Every change reads the file again, applies one change and writes (FD:311-329). The write goes through Lua\ZeD_modfolders_spare.txt first (FD:207-232). Limits: 99 folders (FD:29), names cut at 48 while typing (FD:30). ZeD writes it only when the player changes folders, including every open or close (FD:396-415).
- **Lua\ZeD_modfolders.txt**, ZeD's own: unfiledOpen=<1|0> and label=<folder id>|<label key> per labelled folder (FD:499-554).
- **Lua\ZeD_folder_colors.txt**, ZeD's own: a header line, then <folder id>=<accent key> per colored folder (MF:647-697). Read once per Lua session into a module-local cache (MF:655-669).
- **Lua\ZeD_modprofiles.txt** (and ZeD_modprofiles_spare.txt, with a "-- whole" last line): one section per profile and per list ("[@list main menu]", "[@list save <folder>]", "[@list new game]", "[@list server <name>]"), each with order=, first=, last=, rule=<id>|after or before|<other>, top=, sep=<on>|<open>|<name hex>|<ids>[|<label>], saved=, used=; lines it does not know are kept (OR:46-216). An empty list section is not written (OR:195-196). Written at Done on the Load order page (OP:149, OR:274-280). A spare found whole on load is read instead of the real file (OR:141-142).
- **mods\default.txt**, the game's active list and map order: written by the game's saveModsFile at the Mods screen's Accept (MSM:279); a save's list goes to its mods.txt (MSM:249-252); a server's goes back to its settings (MSM:267-277). Done on these pages changes only the list in memory: correctAndSaveModOrder (MM:672-679, MSM:138-163) and getMapOrder (OP:151-154).
- **Lua\pz_modlist_settings.cfg**, the game's favorites and presets: rewritten by every Accept (MSM:240-242, 344-365). Nothing on these pages writes it directly, but leaving the Mods screen through Accept or Discard does.
- In memory while the Order page is up: the working copy of the list's pins, rules and separators (oLo, OP:122), up to 30 Undo steps (OP:35, 226-233), the dimmed mods' reasons (oOffHere, OP:129), each mod's needs and wishes read once per screen open (OP:70, 76-85; OR:325-345).

**The view: folders on the Mods list (MF:120-185, 381-437):**
- The folders in the file's order, then Unfiled (every mod in no folder; never written to the file). Inside each, the rows as the tab and Find keep them, indented 12 units (MF:425). With a tab or Find, a folder with nothing to show is not drawn and its count reads "n of N" (MF:143-158).

The row and its mods' rows are washed in the folder's Color (MF:315-316, 424). Unfiled has no picture and no box.
- A line over the list while folders exist: on the Mods list "Folders only sort this list."; on the Load order page "LOAD ORDER The mods that are on, top loads first..." (MF:82-108, ZUI:4317-4319).
- A folder's pane (MF:956-1034): the picture and name, "Folder | n mods, k on | from ModFolders.cfg", the verbs (Turn all on or Turn all off, Rename..., Delete folder, Color..., Move up, Move down), Label swatches (None and eight colors, MF:225-294), "In it (n)" with each mod's box, "Not installed (n)" with Take out (MF:1004-1022), "The box" with what a press does and "A folder never changes the load order." ## 2. What the game does for the same jobs (and what ZeD lacks)

- **Folders and separators:** the game has neither. ZeD's folders read and write the [B42]Mod Folders mod's own file, so a layout is the same with or without ZeD (MF:6-10). Separators are ZeD's, Mod Organizer 2 style, kept only in ZeD_modprofiles.txt (SP:7-10); the game's files only ever get the plain order.
- **Load order (MLOP, MOLB):** a panel of the mods that are on (MLOP:21-40); drag by the drag icon (MOLB:19-37, 83-113, a drop below the last row goes to the end); Y and X move (MLOP:315-321, MOLB:276-294); Auto sorts by mod id, each mod's load-after and needs before it, its load-before after it (MLOP:196-254); names green (fine), orange (a wish not kept) or red (only the first mod whose requirement has not loaded yet, MOLB:39-81, MLOP:275-290); Accept greyed while red (MOLB:46); a tooltip per row lists the mod's wished order (MLOP:49-80); Back asks whether to keep a changed order (MLOP:154-182, 292-299); Accept runs correctAndSaveModOrder, which pulls each mod's requirements in ahead of it (MLOP:146-152, MSM:138-163).
- **Map order (MOUI, MPLB):** the maps in order (MOUI:21-32), a tooltip of the maps each shares cells with (MOUI:34-44), drag, Y and X, Help (UI_ModsConflictsInfo, MOUI:128-133), Accept writes getMapOrder (MOUI:110-116), Back discards without asking (MOUI:124-127). The button is always there, enabled only with a clash and colored orange (MSEL:102-115, 266). MAPS holds the default map list ("Muldraugh, KY", MAPS:1-4).
- **Saving:** both panels change only the list in memory; mods\default.txt is written at the Mods screen's Accept (MSM:240-301).
- **What ZeD adds:** Find, pins and their carried mods, your rules with circle checks, Undo, every red row marked (not just the first), a reason on each red row, a pane that explains each need and wish, separators, folders, Move it up.
- **What ZeD lacks or does differently:** no "keep your changes?" on the Load order page's Back (OP:144-171 discards); no Help on Map order; the Map order button is hidden, not greyed (MM:1263); no Undo on Map order (neither has the game's); a drag can't cross a pinned block or move ZeD picks (OP:376-384), where the game's drag goes anywhere; no per-row tooltip (the pane says it instead).

## 3. Gaps and risks

Each line: what to check, the evidence, then the kind (bug, design call or plain check) and whether a Lua script at the main menu can stage it. A script must undo every change to folders, order or on/off before it ends.

**Staging notes.** A script can point ZeD.ModFolders.FILE at a test file so the player's ModFolders.cfg is never read or written (FD:28, as QF does), but ZeD_modfolders.txt (FD:505), ZeD_folder_colors.txt (MF:653) and ZeD_modprofiles.txt (OR:48) have fixed names: save their text first and put it back. The colors cache is module-local and never reloads (MF:655), so a color is put back with ZeD_MMMods.setFolderColor(fid, old), not by rewriting the file; F.load() rereads the labels (FD:237-242). A test file's folder ids collide with the player's: test folder 1 shows the player's folder 1 color and label. Put on and off back through revert (MM:683-698) and leave through Discard (MM:649-657); Discard ends in accept, which writes mods\default.txt and pz_modlist_settings.cfg (MSM:241, 279), so the order must be back before it runs. Can't be staged by script: a real mouse drag (ZeD.MouseTick), a real pad, a failed disk write, a screen size or text size (set before launch), the [B42]Mod Folders mod reading ZeD's file (that mod on and a reload), safe mode.

**Folders**
- **MO1** An unchanged ModFolders.cfg round-trips byte for byte through open, look and close, and one change rewrites only the lines it touched (FD:171-187, 7-10). Plain check; script (QF part 1).
- **MO2** A version 1 file (%XX and %XXXX escapes) reads as the mod reads it, and the first change rewrites every folder and member line and the version line as version 2 (FD:57-97, 318-323). Plain check; script.
- **MO3** A non-ASCII folder name (accented letters, a CJK name, an emoji's surrogate pair) saves as one hex code per UTF-16 unit and reads back the same (FD:41-55); then the [B42]Mod Folders mod reads it too (ZeDUI/tools/qa/modfolders_crossread.lua). Plain check; script for the round trip, by hand for the other mod.
- **MO4** A failed write can lose the file: getFileWriter cuts ModFolders.cfg as it opens, the spare holds the text, but nothing ever reads ZeD_modfolders_spare.txt back (FD:207-232; OR:141-142 does recover its own spare), and the band says "nothing changed" (ZUI:4361). Bug (suspected, low); by hand.
- **MO5** A deleted folder keeps its color and label: F.delete drops only its lines (FD:382-393); ZeD_folder_colors.txt (MF:692-696) and label= (FD:536-542) keep the id. Ids are never reused while next= holds (FD:127-130), but a ModFolders.cfg deleted or reset outside starts at 1 again, and a new folder 1 shows the old folder 1's color and label. Bug; script (save and restore both ZeD files).
- **MO6** Two color controls on one folder: the pane's Label swatches write ZeD_modfolders.txt and tint the folder picture (MF:985-990, 327-332), Color... writes ZeD_folder_colors.txt and washes the rows (MF:700-712, 315-316, 424). A folder can show a blue picture on a red row; Start separators from folders carries only the Label (SP:1044); the label's help names only the picture (ZUI:4608). Design call; script.
- **MO7** The Color menu lists None and eight colors with the game's color names, the current one ticked; the comment says nine accents (MF:699, 704-709; ST:34-36, mono skipped). Plain check; script.
- **MO8** The moved count overstates: folderMove says "%1 mods are in X now" with the number picked (MF:577-581, ZUI:4356), not the number F.assign moved (FD:439-483). Pick five, three already in the folder: it says five. Bug (low); script.
- **MO9** At 99 folders, New folder... greys in the band and both menus (MF:614-615, 733, 766-768). If the file reaches 99 another way while the name field is open, F.create refuses (FD:355) and the band blames the file: "ModFolders.cfg could not be written" (MF:801-805). Bug (wording, low); script (a test file with 98 folders, then a line added).
- **MO10** A name used by another folder, in any case, greys Make and says so; a rename that changes only the case is allowed (FD:281-290, MF:858-869). Plain check; script.
- **MO11** Typing stops at 48 letters (MF:876); a longer name from the file stays and truncates on the head and the pane (MF:339-341, 979). Plain check; script.
- **MO12** Delete folder asks with the count of installed mods only (MF:846-851); the not-installed member lines go too (FD:387) and the question does not say so. Design call; script.
- **MO13** Open and close: the triangle, a double-click within 450 ms, A; refused with a note while Find has text (MF:458-463); each one rewrites ModFolders.cfg (FD:396-403); Unfiled's state goes to ZeD_modfolders.txt (FD:549-554). A focused mod row hidden by a close moves the focus to its folder (MF:472-477). Plain check; script.
- **MO14** The box on a mixed or empty folder turns all on in one batch, requirements "came along", a mod that can't run is named (MF:503-508, 536-546); on an all-on folder it turns all off one at a time, and on a save's list a mod the world may hold stays on (MF:509-518). Plain check; script (revert after).
- **MO15** Turning a folder on lays the order out again only when the list has pins, rules or separators (OP:89-97, OR:268); a newly on mod lands at the end above Load last and under the last separator (OR:556-560). Plain check; script.
- **MO16** Picked rows a tab or Find now hides still move with Move to folder (MF:557-560); Shift-click spans only visible rows (MF:1050-1061); Escape drops the pick (MF:1242-1245). Design call (hidden rows move); script.

- **MO18** Keys on the grouped list: Shift+F10 and the menu key open the row's menu at the row, Page Up and Down jump folder to folder, Space, F2 and Delete on a folder row, Up and Down from a picked folder (MF:1199-1238). Plain check; by hand (a script can call keyOther, but the real keys are the test).
- **MO19** An edit made outside while the screen is open: a change rereads the file and keeps it (FD:313-315), but the list shows outside folders only after the Mods page opens again (MF:65-70); a move into a folder deleted outside says it is gone (MF:571, FD:442). - **MO20** Lines ZeD can't read show as "ModFolders.cfg has n lines ZeD could not read" on the status line and stay where they were through a change (MF:1171-1172, FD:160-162). Plain check; script.
