# ZeD-GUI deep tests and audits, night of Nov 19 to 20 2026

For the director. Written by QA on beta 21 as shipped. Plain summary first; the detail is in the four audit files
next to this one.

## The short version

1. **Speed is the big finding.** With both windows shut, ZeD costs nothing you can measure. With them open at 4K,
   the game drops from about 120 frames a second to between 38 and 55. In October the same test held 120. The
   machine is not slower (a raw draw costs the same as in October); the mod's own code is. Most of it arrived after
   Nov 8, not in beta 21.
2. **The bug hunt found ten real bugs in beta 21's new parts** (the tour, the keyboard map, the first-launch
   window, the move from Simple to Lite) and six more that need a run to prove. Build is fixing them tonight.
3. **The same facts are shown two, three and four times** on most windows. 49 places are listed, with a fix for
   each. None is applied: every one changes the look, so each is yours to approve.
4. **About 3,800 lines of code, 21 pictures and about 150 phrases in each language do nothing any more.** They can
   go before 1.0. The setup page can go from 56 rows to about 42 without changing what any saved setting means.
5. **Everything else held.** The release test passes with Large text at Deck size (1 failure, caused by my own
   setup). All text colors pass the contrast check in every theme. Every phrase the code asks for exists.

## 1. Speed (measured in game, 4K, UI scale 1.75x)

Milliseconds for one frame; lower is better. 8.3 ms is 120 frames a second, 16.7 ms is 60, 25 ms is 40.

| What is on screen | Oct 29 | Tonight, Full | Tonight, Lite |
|---|---|---|---|
| Windows shut (belt, watch, moodles) | 8.4 | 8.5 | 8.9 |
| Both windows on Loot | 8.4 | 18.1 | 19.8 |
| An item card open | 9.3 | 20.7 | 17.9 |
| World window on Maps | 8.6 | 26.2 | 20.9 |
| World window on Craft | 8.6 | 21.8 | 16.2 |
| Character window on Health | 9.0 | 24.8 | 18.8 |
| Character window on Skills | 8.6 | 22.5 | 19.1 |
| Character window on Equipment | 8.7 | 25.3 | 19.2 |

The same windows by another script, against Nov 8 (ms a tick): Character on Loot 17.5 (was about 11), World on Loot
21.4 (about 10), Skills 25.2 (about 17), Equipment 22.3 (about 19), Thermal 20.3 (about 15).

Where the time goes:

- **The two item lists.** Each list costs about 3.3 ms to draw (1.5 ms in October) while drawing the same things.
  Both lists keep drawing whatever tab is open beside them, so they are half the frame in every row of the table.
  The cause is work done for every row on every frame: each row asks the game for its name, picture, weight and
  condition again, and a stack of fifty asks fifty times.
- **Text.** Drawing one piece of text costs about 7 millionths of a second through the mod's text code, against
  under 1 for the draw itself. Every Lua window in the game goes through that code, other mods' windows too.
  Measuring a text's width costs the same again.
- **The Health and Skills panels** cost four to six times what they did in October.
- **Lite is not faster by design.** It is 2 to 6 ms lighter on most tabs because it draws less, but it has the
  same drop.

What is being done: Build is taking the per-row work out of the item list tonight. The text code is shared by
every window in the game, so Build will not rush it at night; it is first on the list after tonight, with these
numbers as the target.

Not measured tonight: driving (the dashboard). The speed audit read the code and found the dashboard reads the
whole car and the radio again on every frame, and that its needle cache never hits.

## 2. Bugs found in beta 21's new parts

Confirmed by reading the code line by line (ZeDUI/qa/audits/2026-11-20_bug_hunt.md has the steps for each):

1. Keyboard map: change a key, then press Apply anywhere in Options in the same session, and the key goes back.
2. Tour, mouse: the Character window rolls itself up about two seconds after each step shows, while the balloon
   is still describing it.
3. Tour, Full style, a watch worn: the "Your watch" balloon points at the top left corner of the screen.
4. Tour: if the player takes the game's own Tutorial first, ZeD's tour starts inside it, shows blank steps, and
   then never shows in the real game.
5. Coming from beta 20 with any Simple pick: everything is Immersive again and nothing says so. (Build's fix:
   all eight old switches on becomes Lite, once.)
6. Keyboard map on a French (AZERTY) keyboard: Reset writes the wrong keys.
7. Controller: Start does nothing during the tour or the keyboard map, and the character cannot move while the
   tour is up.
8. Picking Lite from the first-launch window or the controller wheel leaves the extras on, with no row to turn
   them off.
9. Keyboard map: a key saved with Shift, Ctrl or Alt shows without it, and a rebind keeps the modifier.
10. Lite, controller, appliances with separate On and Off keys: the highlight vanishes on one of them.

Also found by the other audits: every item ever hovered is kept in memory until the game closes; a finished book
keeps its reading band; two timers run 2.4 times as fast on a 144 Hz monitor; a Vanilla Plus player from beta 20
with one Simple pick reads Custom with no row to fix it; two test pictures ship in the mod.

Thirteen visual bugs, mostly text cut off with room beside it ("Tool / ...", "Fire So...", "Ange...", long radio
and tire names), the World window covering the Lite clock when Crafting or Maps is open, and a black blob where
the Light theme's column icon should be.

## 3. Visual redundancy and noise (proposals; nothing applied)

The full list is ZeDUI/qa/audits/2026-11-20_visual_noise_audit.md: 49 findings, ranked, each with its picture.
The twelve with the most to gain:

1. The item count is shown three times and the weight twice on each inventory window (title bar, header, foot).
2. An empty container says so four ways ("0 items" three times and "Nothing here.").
3. The tab's name is stacked two to four times ("Ground + Crafting", "Crafting", "Station: Microwave", "Microwave").
4. The plain appliance card repeats its labels on its buttons ("Power level Med [Power level]").
5. The plain radio card shows the frequency twice and power three ways.
6. The Lite clock prints "Speed x1" right above a lit "x1" button.
7. The Mods screen counts the mods three times, and in Lite still shows a caption about folders.
8. Question windows have an empty title bar, the title in the body, a menu box and an empty strip at the foot.
9. The foot strip of every window is blank most of the time.
10. Sliders show their value twice.
11. Vehicle part rows show condition three ways.
12. Skills rows show the level as a number and again as a bar.

Lite against Full: Lite is truly simpler on the belt, the Mods screen, the setup page and the item card. It is
wordier than Full in the column header and on the plain radio, appliance and clock cards.

ZeD setup: 56 rows show today. Two audits, working apart, both land near 42 to 45: drop the rows that already
have a control on the window itself, merge the three wheel options, the three read-mark switches and the seven
Safe mode switches, and show the test rows in debug only.

## 4. Needless complexity (for 1.0)

ZeDUI/qa/audits/2026-11-20_complexity_audit.md. About 3,800 lines nothing runs: leftover data from the first
watch, radio and siren art (1,018 lines, 19 pictures), an early parts library (about 1,280 lines), the plain
dashboard strip Lite retired (about 690 lines), the eight old Simple switches, 149 unused phrases in each of 28
languages. The same small helpers are written 30 to 40 times each. QA's own folder has about 630 scripts to
archive. My advice: Build takes the deletions as their own pass with a full release test, not tonight.

## 5. What held

- Release test with Large text at Deck size: 12 of 13 scripts pass; the one failure was my setup (Large switched
  on without saving the option, so Discard rightly took it back).
- Contrast: 7,560 pairs of text color on surface, every theme, accent and status set. Every text color passes.
  Weak as dots and tags only: the Light theme's warning color (worst with the color-blind set), Dark's grayed
  text on raised surfaces (just under 3 to 1), and a few accent dots.
- Every phrase the code asks for exists in English.
