# ZeD-GUI deep tests and audits, night of Nov 19 to 20 2026

For the director, from QA. Beta 21 as shipped was tested and audited from 00:55 to 03:45; Build fixed what could be
fixed safely at night and QA checked each fix in game. The four audit files next to this one hold the detail.

## The short version

1. **Speed was the big finding, and part of it is already fixed.** With both windows shut, ZeD costs nothing you
   can measure. With them open at 4K, beta 21 ran at 38 to 55 frames a second; in October the same test held 120.
   The machine is not slower; the mod's code was. Tonight's fixes bring it to 53 to 72 frames a second and win
   back everything lost since Nov 8. The rest (the text code every window shares) is Build's next job.
2. **The bug hunt found ten real bugs in beta 21's new parts** and six more that needed a run to prove. Ten are
   fixed and checked in game tonight; the rest are listed below with what each needs.
3. **The same facts are shown two, three and four times** on most windows. 49 places are listed with a fix for
   each. None is applied: every one changes the look, so each is yours to approve.
4. **About 3,800 lines of code, 21 pictures and about 150 phrases in each language do nothing any more.** They can
   go before 1.0. The setup page can go from 56 rows to about 42 without changing what any saved setting means.
5. **Everything else held.** The release test passes at Large text (Deck, 4K and 1280x720), in High contrast, and
   in the Light theme with Lite. Every text color passes the contrast check in every theme.

These fixes are in the project but **not on the Workshop**: beta 21 as uploaded does not have them. They need a
hotfix upload, which is your call.

## 1. Speed (measured in game, 4K, UI scale 1.75x)

Milliseconds for one frame; lower is better. 8.3 ms is 120 frames a second, 16.7 ms is 60, 25 ms is 40.

| What is on screen | Oct 29 | Beta 21 | After tonight's fixes | Beta 21 in Lite |
|---|---|---|---|---|
| Windows shut (belt, watch, moodles) | 8.4 | 8.5 | 8.4 | 8.9 |
| Both windows on Loot | 8.4 | 18.1 | 13.8 | 19.8 |
| An item card open | 9.3 | 20.7 | 15.9 | 17.9 |
| World window on Maps | 8.6 | 26.2 | 18.3 | 20.9 |
| World window on Craft | 8.6 | 21.8 | 14.9 | 16.2 |
| Character window on Health | 9.0 | 24.8 | 18.8 | 18.8 |
| Character window on Skills | 8.6 | 22.5 | 18.8 | 19.1 |
| Character window on Equipment | 8.7 | 25.3 | 18.9 | 19.2 |

By a second script, against Nov 8 (ms a tick): Character on Loot about 11 then, 17.5 in beta 21, 11.8 now; World
on Loot about 10, 21.4, 11.0; Skills about 17, 25.2, 17.8; Equipment about 19, 22.3, 19.2.

Where the time went:

- **The two item lists.** Each cost about 3.3 ms to draw (1.5 ms in October) while drawing the same things, and
  both keep drawing whatever tab is open beside them. Each row asked the game for its name, picture, weight and
  condition again on every frame. Fixed tonight: a row now keeps what it learned for a quarter second.
- **The row of container buttons** counted every item in reach four times a second. Fixed: it recounts when
  something changes.
- **Text.** Drawing one piece of text costs about 6 millionths of a second in the mod's text code against under 1
  for the draw itself, and measuring a text's width costs the same again. Every Lua window in the game goes
  through that code, other mods' too. Not fixed tonight: it is shared by everything, so Build will do it by day.
- **Lite is not faster by design.** It draws a little less, so it is 2 to 6 ms lighter on most tabs.

The machine was checked first: a raw draw costs the same today as on Oct 22, so none of this is the PC.

Not measured: driving. The speed audit read the code and found the dashboard reads the whole car and the radio
again on every frame. Part of that is fixed (the needles); the rest is on Build's list.

## 2. Bugs in beta 21's new parts

Fixed tonight and checked in game:

1. Keyboard map: a changed key went back to the old one the next time Apply was pressed anywhere in Options.
2. Tour, mouse: the Character window rolled itself up two seconds into each step while the balloon was still
   describing it. (Seen in three runs before the fix, held open in every run after.)
3. Tour, Full style, a watch worn on the belt: the "Your watch" balloon pointed at the corner of the screen. The
   step is now passed over when the watch has no box of its own.
4. Keyboard map: a double click on Reset could wipe every key. The second press now counts from 0.3 seconds.
5. A setup file with values no option has (theme 9 of 3, a word where a number belongs) was taken as it stood
   and saved. Only values an option really has are taken now.
6. Picking Lite on the controller wheel left the extras on, with no row left to turn them off.

Fixed tonight by Build. The release test passes with them in, but QA has not yet checked each one by itself:

7. Tour starting inside the game's own Tutorial, then never showing in the real game.
8. Coming from beta 20 with Simple picks: all eight old switches on now becomes Lite, once.
9. Picking Lite in the first-launch window left the extras on.
10. Controller: Start did nothing during the tour and the keyboard map.
11. Keyboard map: a key saved with Shift, Ctrl or Alt showed without it.
12. Lite, controller, appliances with separate On and Off keys: the highlight vanished on one of them.
13. The tour now closes when the character dies.
14. Every item ever hovered was kept in memory until the game closed; a finished book kept its reading band; two
    timers ran 2.4 times as fast on a 144 Hz monitor; a Vanilla Plus player from beta 20 with one Simple pick read
    Custom with no row to fix it.
15. Six of the thirteen visual bugs: the World window covering the Lite clock, a cut-off character name, cut-off
    help lines, farm plot lock tags drawn over the bars beside them, the Light theme's black blob where a column
    icon should be, and the "2 conflicts" chip's black backing.

One fix broke something and was caught: the controller fix made every controller press on the tour throw an
error. The tour test caught it within minutes and Build fixed it at once.

Still open:

- Keyboard map on a French (AZERTY) keyboard: Reset writes the wrong keys. Needs that keyboard layout to see.
- Keyboard map: the key pressed to answer the map may also do its job in the game. Needs care; Build left it.
- Cut-off text: the Cat column ("Tool / ...", "Fire So..."), a stack's name, mod pane labels, tire and radio
  names. The last two are a look change (shorter names), so they are yours.
- Crafting says "Required (2/2)" in green with Craft dimmed, and "Show: Ready" lists a 0/7 structure. Needs a look.
- A five-character date such as "12-25" on the smallest drawn watch may touch the weekday. Needs a December date.

## 3. Visual redundancy and noise (proposals; nothing applied)

The full list is 2026-11-20_visual_noise_audit.md: 49 findings, ranked, each with its picture. The twelve with the
most to gain:

1. The item count is shown three times and the weight twice on each inventory window (title bar, header, foot).
2. An empty container says so four ways ("0 items" three times and "Nothing here.").
3. The tab's name is stacked two to four times ("Ground + Crafting", "Crafting", "Station: Microwave", "Microwave").
4. The plain appliance card repeats its labels on its buttons ("Power level Med [Power level]").
5. The plain radio card shows the frequency twice and power three ways.
6. The Lite clock prints "Speed x1" right above a lit "x1" button.
7. The Mods screen counts the mods three times, and in Lite still shows a caption about folders.
8. Question windows have an empty title bar, the title in the body, a menu box and an empty strip at the foot.
9. The foot strip of every window is blank most of the time.
10. Sliders show their value twice.
11. Vehicle part rows show condition three ways.
12. Skills rows show the level as a number and again as a bar.

Lite against Full: Lite is truly simpler on the belt, the Mods screen, the setup page and the item card. It is
wordier than Full in the column header and on the plain radio, appliance and clock cards.

ZeD setup: 56 rows show today. Two audits, working apart, both land near 42 to 45: drop the rows that already
have a control on the window itself, merge the three wheel options, the three read-mark switches and the seven
Safe mode switches, and show the test rows in debug only.

## 4. Needless complexity (for 1.0)

2026-11-20_complexity_audit.md. About 3,800 lines nothing runs: leftover data from the first watch, radio and
siren art (1,018 lines, 19 pictures), an early parts library (about 1,280 lines), the plain dashboard strip Lite
retired (about 690 lines), the eight old Simple switches, 149 unused phrases in each of 28 languages. The same
small helpers are written 30 to 40 times each. Two test pictures ship in the mod today. QA's own folder has about
630 scripts to archive. Nothing was deleted tonight; Build will take the deletions as their own pass with a full
release test.
