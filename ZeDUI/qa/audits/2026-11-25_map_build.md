# Build tab: map for the gamut sweep (QA, Nov 25 2026)

A read-only map of ZeD's Build ("Building") tab in the World window against the game's own build window, written before the bd_ sweep scripts. Line refs are as read on Nov 25 2026 (no git run). Nothing was launched.
Short names, ZeD: BT BuildingTab.lua, CC CraftingCore.lua, WW ZeD_WorldWindow.lua, OCP ObjectCardPreview.lua, STO Overrides/Stations.lua, FM Input/FocusManager.lua, PIP Overrides/PlaceItemPad.lua, ORG Organisms.lua.
Short names, the game (media/lua): BP client/Entity/ISUI/BuildRecipe/ISBuildPanel.lua, WBC .../BuildRecipe/ISWidgetBuildControl.lua, EUI client/Entity/ISEntityUI.lua, BO server/BuildingObjects/ISBuildingObject.lua, BIE server/BuildingObjects/ISBuildIsoEntity.lua, BA client/BuildingObjects/TimedActions/ISBuildAction.lua, BM client/BuildingObjects/ISUI/ISBuildMenu.lua, MS client/OptionScreens/MainScreen.lua.
FEATURE_MAP row 249 cites startBuild :297 and onClick :433; they are now BT:309 and BT:450.

## 1. What the tab does

**Getting there:**
- The tab strip: tab id "build", named UI_ZeD_World_TabBuilding (WW:133). It uses the 480 drawer (WW:74, 1871).
- Every game way into the build window is routed here by the hook on ISEntityUI.OpenBuildWindow (STO:133-149). That covers the Build key (XpUpdate.lua:141-149), the sidebar Build button (ISEquippedItem.lua:485-490), the pad's back-button wheel "Building" (ISBackButtonWheel.lua:136-142), an item menu's recipe list (ISInventoryPaneContextMenu.lua:1236, 1251, 1274), an item's "Build" list (1302-1304) and a magazine's recipe list (ISLiteratureUI.lua:568).
- ZeD's own ways in: the D-pad wheel slice "Building" (ZeD_DpadWheels.lua:1169), the Journal's "Open in Build" (JournalTab.lua:1480-1489, through RecipeIndex.lua:229-235) and LB/RB between the windows.
- A plain open (the key, no recipe) toggles. A second press closes the World window only if that key opened it; otherwise it folds the tab (WW:7020-7026).
- An open with a recipe sets Category to All, clears the search and opens the card on it (STO:51-64). An open with an item puts the item's name in the search (STO:33-46). It retries for 30 ticks until the state exists (STO:66-74).
- Safe mode gives the game's own window (STO:136).
- The pad takes the window on its first stop when nothing else holds it (STO:105-114).

**Data (BT:20-270):**
- The catalog is built once per Lua session from BuildLogic:getAllBuildableRecipes (BT:26-204). `_catalogBuilt` is set first, so a failure leaves it empty for the session (BT:28-50).
- Each entry gets:
  - a category: getCategory, then getBuildCategory, then the first skill's name, else "miscellaneous" (BT:63-96);
  - inputs, outputs and skills, pre-baked (CC.prebakeInputs 775-863, prebakeSkills 927-937);
  - the tool slots (BT:107-117);
  - the icon, and the recipe's Tooltip text as its description (BT:123-136);
  - needLearn, true for metal and welding (BT:144-146).
- Rows are refreshed once a second (ROWS_MS, BT:210-270). Each row reads hasSkill from the game's characterHasRequiredSkills (BT:244-247) and learned from isRecipeKnown(recipe, true) (BT:252-257).
- Ready means the game's own answer. CC.logicScan (CC:445-532) asks BuildLogic:getCachedRecipeInfo every 1.2 s. setContainers and setRecipes are called again on a changed signature (the container item counts and weights, recipes known, every skill level, the square) or every 6 s (CC:408-409, 418-431). Rows the game didn't answer get the round-robin quick scan, 15 a frame, whole items only (CC:357-387).
- Containers are the game's list, ISInventoryPaneContextMenu.getContainers: the inventory, bags, the floor and open loot containers. The carried list is used only as a fallback (CC:163-171).

**Header (CC:1772-1843):**
- Category select on the left (45%) and the search on the right, placeholder "Search structures..." (WW:4459-4477, CC:1739-1741). There's no Station box on Build.
- Category labels come from IGUI_CraftingCategories_<Name>, else the raw word (CC:976-993).
- Search matches the name, the category's raw word, every ingredient type's name and the output names (CC:1121-1148). While searching, Show is ignored (CC:1156).

**List (CC:2265-2575):**
- Sections: Pinned (ZeD pins, modData ZeD_BuildPins, at most 8, the oldest dropped on the 9th, CC:693-715), Most used (top 5 from ZeD_BuildCounts, CC:743-769), then "All structures" or "Results" while searching (CC:2340-2347).
- A lone section has no head and can't fold (CC:2352).
- Rows show the icon, the name and a status dot: can, miss or unknown (CC:2499-2506).
- Click opens the card. A second click keeps it (CC:1542-1551, KISS #47). Right-click or the star toggles the pin (CC:3828-3833, 3930-3946).
- An empty list says why (CC:2558-2560, 1035-1040).

**Band (CC:2064-2163):** Sort (Craftable, Known, Name, Freq), Show (Ready, Known, All) and Build. Build opens on Show: Known (BT:412). Known hides recipes not learned or short of skill (CC:1156-1160). Build has no amount: maxBatchQty is 1 (BT:280), so there's no - n + and no Max (CC:1989). The Build key is grayed unless status is craftable and the recipe learned (CC:1972), but its zone is stamped whenever a recipe is picked (CC:2058).

**Card (CC:3041-3393), on the right half of the split (240 + 240, CC:42-43, 3548-3562):**
- Header: the icon (a press opens the preview card, CC:3136-3156), the name and the description cut to one line (CC:3159-3172).
- Chips: "Unknown" when not learned or short of skill (CC:3178-3184), then the time (CC:3189-3201).
- "Required (have/need)" lists each input's have/need (whole items, CC:1330-1351) with a TOOL or KEEP tag (CC:963-970). A row with alternatives opens the alternatives list (CC:3327-3336, 3882-3889). The list can't pick anything on Build; picks are Craft only (CC:3436-3439).
- A "stuck" line shows when every row is green but the game says no (CC:3084-3104). It asks a HandcraftLogic which input is short, else words it as "Needs a table" or "Needs a workbench".
- "Creates" is hidden when it repeats the title (CC:910-924, 3352).
- No skill rows: those are the Journal's only (CC:3060).
- Escape closes the card when it was drawn in the last 0.5 s (CC:1556-1572, through Prompts.lua:161-163).

**Preview card (OCP, kind "preview", the half card):**
- The build's tiles laid per face, with < and > to step faces (OCP:353-392), the game's words, Strength by the game's formula (OCP:101-145) and Skill (OCP:146-148).
- Its verb "Build" shuts the card and runs startBuild (OCP:307-315). It's enabled only when the drawer's row is craftable, learned and skilled (OCP:302-306).
- It closes when another recipe is picked (OCP:41).

**Build pressed (BT:309-388, CC:2881-2884):**
1. A fresh BuildLogic gets getAllBuildableRecipes, setRecipes, setRecipe and setContainers with the game's list read now (BT:320-332).
2. If canPerformCurrentRecipe is false and the player's BuildCheat is off, it returns with nothing said (BT:336-338).
3. Otherwise it makes ISBuildIsoEntity(nSprite 1) with dragNilAfterPlace false and blockAfterPlace true, sets the tool items and calls setDrag (BT:348-361).
4. Wall coverings get ISPaperCursor or ISPaintCursor instead (BT:363-375).
5. The count goes up when the cursor starts (BT:377-380), and the caches drop (BT:382-387).
6. The card stays open, and so does the World window. Nothing hides it as the game's window hides (BP:428-445); it rolls up 2 s after the pointer leaves unless pinned (WW:3959, ORG:182-229).

**Placement:** it's the game's cursor throughout.
- Tint: BIE:isValid (444-485). Mouse: click to place, drag to turn (BO:97-178). R rotates player 1's cursor only (BO:583-597).
- tryBuild walks, equips and queues ISBuildAction (BO:180-289). After one placement, blockAfterPlace sets blockBuild (BO:213-216).
- The materials are consumed by the logic in BIE:create (549-560); a failed consume builds nothing.
- Cancel: Esc (MS:1713-1716, after ZeD's Escape takers), right-click (ISMenuContextWorld.lua:52, 222), pad B (BO:629-631).
- Neither a tab switch nor closing the World window clears the cursor. Furniture's cursor replaces it (FurnitureTab.lua:172-181).

**Dismantle and pick-up:** not on this tab. They live in the Furniture tab's Scrap and Pick up modes (FurnitureTab.lua:39-45) and the game's world menu. Menu guess keeps Dismantle, Disassemble and Destroy out of guessed picks (ZeD_MenuGuess.lua:94-95). The 3D Placement card (ObjectCardPlacement.lua) is for items lying in the world and doesn't tie in.

**Pad (CC:4109-4469, WW:1216-1220, 5385-5530):**
- Stops: build:catDrop, then build:search (A opens the pad keyboard, CC:4441-4464), build:section:<pinned/freq/all> (only when more than one section), build:row:<name>, build:icon, build:card:req, build:card:out, build:slotAlt:<input>, build:altBack, build:altOwned, build:sortMenu, build:showMenu and build:actBuild. Open lists lock the focus to build:cat:<id>, build:sortRow:<id> or build:showRow:<id>.
- No build:altPick, actQty, actDec, actInc or actMax on Build.
- A on a row opens the card and the focus jumps to build:actBuild once it's stamped (CC:4178-4190, WW:5416-5440). X on a row pins (CC:4195-4200). B shuts an open list. Elsewhere B has no onCancel and stops a running action, the game's B (FM:1696-1704); it doesn't close the card. Y hides the pair.
- After A on Build, the windows roll up once per cursor (FM:3200-3216), or the press is handed to the cursor (FM:2518-2527, ORG:1858).
- On the cursor: the D-pad moves the tile, LB and RB turn it, B cancels (BO:627-669). The cursor has no A case. ZeD's A fix wraps Place item only (PIP:17-28). PIP's guard turns the Interact key off while any cursor is up (PIP:58-80).
- The bumper chord comes back once the windows let go (BumperChord.lua header).

**Small screens:** the drawer is 480 split 240/240; names are cut (CC.truncText). The band goes narrow and shrinks Sort and Show (CC:1995-2011, 2122-2163). The preview picture box is 220 units tall (OCP:30), so the half card scrolls at 720.

**Lite:** no branch in BT, CC or OCP.

**Settings:** UI scale, text size, theme, the language, safe mode. Show and Sort aren't saved: toggle() rebuilds the window each open (WW:4037-4040). Pins and counts live in modData.

## 2. Against the game (steps)

| Job | Game | ZeD Build tab |
| --- | --- | --- |
| Open the list | Build key or sidebar (1) | the same key, routed (1); the strip (1 or 2); the D-pad wheel |
| Close it | the key again (1) | the key again, only if it opened the window, else the tab folds |
| Find one | category column (1) and scroll; search (click, type) | Category (2); search (click, type); opens on Known, skill-short hidden |
| Start placing | pick (1) and Build (1), or a double-click (1) | pick (1) and Build (1); a double-click only opens the card |
| Place | click the tile (1), drag to turn | the same cursor |
| Turn | R, mouse drag, LB and RB | the same; the preview's facing is not carried |
| Build another | click again once the first ends (re-armed, BP:414-422) | cancel, Build, click (3): the cursor stays blocked |
| Cancel | Esc or right-click (1); closing the window | right-click (1); Esc (1, or 2 while the card is drawn); closing the window leaves it |
| Pad start | back wheel, A on a recipe, A on Build | back wheel or D-pad wheel, A on a row (focus jumps to Build), A |
| Pad place | A (to prove), LB and RB, B | the same cursor |
| From an item | its Build list: the window filtered by input | the search filled with the item's name |
| From a magazine | the window on the recipe | the tab with its card open |
| Choose which planks | the manual-select inventory panel | none: the alternatives list can't pick |

**ZeD shows, the game doesn't:** Pinned and Most used, Sort by Freq, Show: Ready, the preview card (tiles per face, strength, skill), have/need per input in one list.
**The game shows, ZeD doesn't:** manual input picking, grid view, the game's favourites, the skill on the card, and the Build button grayed while a build is in progress (WBC:163-172).

## 3. States to sweep

- **Run mode:** -debug sets ISBuildMenu.cheat on (BM:2). That skips the walk, the hammer check, waitToStart and the after-place block. Set ISBuildMenu.cheat and the player's BuildCheat off for the run, as bx_craft does (467-468), and put them back.
- **Skills:**
  - Carpentry 0, one short, exactly met;
  - a recipe whose second skill is short;
  - a need-to-learn recipe (MetalBigMetalFence) unlearned, then learned while the tab shows;
  - a level-up while the tab shows.
- **Materials:**
  - all carried;
  - all in a worn bag; in a bag that's carried but not worn;
  - on the floor at the feet; in an open crate beside;
  - split across those; one short; exact;
  - dropped while the tab shows (the row must turn within about 1.5 s).
- **Tools:**
  - hammer, saw, screwdriver; a broken hammer only;
  - a blowtorch nearly empty and a welding mask;
  - a nearly empty paint can or glue.
- **Recipes:**
  - a crate (simple);
  - a wall frame (wall-like walk);
  - a double gate (multi-tile, 4 faces);
  - stairs (walk to the bottom);
  - a barricade;
  - an against-wall object; a pole; an auto-rotate recipe;
  - paint, wallpaper and plaster (the other cursors).
- **Cursor:**
  - valid and invalid tiles (a wall, water, an occupied tile, another's safehouse in MP);
  - each of 4 facings by R, by drag and by LB/RB;
  - place one, then try a second without re-pressing;
  - cancel by Esc (pointer inside the window, outside under 2 s, outside after 2 s, window pinned), by right-click and by pad B;
  - the World window closed and the tab switched with the cursor up; Furniture opened with it up;
  - Build pressed twice; Build pressed while a build runs;
  - B on the card while a build runs.
- **Lists:**
  - Show Ready, Known and All; each Sort; each Category;
  - search with no match, an ingredient word, an output word, a category word in English and in another language;
  - a 9th pin; Most used after builds and after cancels.
- **Entry points:** every one in section 1, plus safe mode.
- **Pad:** walk every stop; A A from a row; search by pad keyboard; X pin; the alternatives; the preview by the icon and B back; placing, turning and cancelling on the cursor; bumpers held while turning.
- **Layout and language:** 1280x720 and 1280x800, Large text, UI scale 2, Light and High contrast, a long-word language (DE or RU), Lite.

## 5. Suspicions (to prove in the game)

- **B1:** on a pad the build cursor may never place. BO:627-653 has no A case and DoTileBuilding's pad branch never sets build (BO:115-117). PIP fixed the same gap only for Place item (PIP:17-28), and its guard also turns off Interact while any cursor is up (PIP:58-80). So A may do nothing at all.
- **B2:** after one placement the cursor stays up and every tile reads invalid. ZeD sets blockAfterPlace (BT:352), tryBuild then sets blockBuild (BO:213-216), and only the game's panel re-arms it, through the logic's onStopCraft listener (BP:414-422, 460). ZeD's logic has no listener (BT:323-332). The player must cancel and press Build again.
- **B3:** Build can be pressed again while a build is queued or running. There's no isCraftActionInProgress gate (BT:336-338 against WBC:165-170, BP:332-334), and the row stays craftable until the scan sees the materials go. The second build may run its walk and full action, then fail its consume (BIE:549-560) and build nothing. Prove whether anything is lost.
- **B4:** Esc with the cursor up closes the recipe card first whenever the card was drawn in the last 0.5 s (CC:1556-1572, run before ToggleEscapeMenu, Prompts.lua:161-163). That holds within 2 s of the pointer leaving the window, or always while the window is pinned (ORG:145, 221-228). The game's Esc drops the cursor first (MS:1713-1716).
- **B5:** the cursor outlives the window. Nothing in BT or WW clears the drag on close or tab switch, where the game clears it on close (BP:405-407). The World window also stays over the tiles while placing, where the game hides its window (BP:428-445).
- **B6:** wrong facing. The preview opens on the N face (OCP:36, 68-93) and its < > choice is never passed on. The cursor starts at nSprite 1, the W face (BT:350, BIE:788-793). The preview's > steps N, W, S, E, the opposite way to RB on the cursor (W, N, E, S, BO:640-645).
- **B7:** the logic's containers are frozen at the press (BT:320, 330, 350), where the game re-reads them as the player moves (BP:185-221). After a walk to a far tile, are materials taken from a crate or floor near where Build was pressed, or does the consume fail? Compare with the game.
- **B8:** a grayed Build still takes the press: the zone is stamped whatever canCraft says (CC:1972, 2058; pad CC:4426-4434). startBuild's own check is the only gate (BT:338). With BuildCheat on, it starts a cursor with nothing carried. When the row says craftable but the game says no, nothing happens and nothing is said.
- **B9:** a card that's all green while Build is gray, with no reason given:
  - Have counts take whole items of any condition (CC:241-259, 1330-1351), so a broken hammer counts.
  - A uses-based input (paint, glue, a blowtorch) needs 1 item whatever its uses (CC:819-830).
  - The stuck line asks a HandcraftLogic about a build recipe (CC:3015-3038) and has words only for a table or a bench (CC:3091-3104).
- **B10:** the card never names the skill. Skill rows are the Journal's only (CC:3060), and a recipe short of skill wears "Unknown" (CC:3178-3184) even when it needs no learning. Show: Known hides it outright (CC:1159). Only the preview names the skill (OCP:146-148).
- **B11:** on the pad, B on the build card doesn't close it. With no onCancel it stops the running action, perhaps the build itself (FM:1696-1704). A second A on the row keeps the card (CC:1542-1551). The only ways off are another row or Y.
- **B12:** on the pad, A on a row jumps the focus to Build (WW:5416-5440), even when Build is grayed. A A from a grazed row starts a cursor and rolls the windows up.
- **B13:** the catalog is built once a session (BT:20-28). A failed first build leaves the tab empty until Lua reloads (BT:31-50), and player 2 or a new character gets the first catalog. Prove getAllBuildableRecipes is player-free.
- **B14:** getTool asks a script item for getFullType (BT:294), which script items lack (OCP:155-156), so tools are never found. Even if found, it hands the cursor an InventoryItem where the game passes a type string (BP:233; used as a type at BO:242-266). No vanilla build script has ToolRight, ToolLeft or ToolBoth, so only modded recipes would hit it.
- **B15:** a build is counted when the cursor starts, not when it's built (BT:377-380), so cancels feed Most used. The 9th pin silently drops the oldest (CC:708-710). The game's favourites aren't read.
- **B16:** the alternatives list opens on Build but nothing in it can be picked (CC:3438); its rows read as choices.
- **B17:** a -debug run hides B2 and skips the walk (BM:2; BO:212-216, 386-392; BA:57-58) unless the script sets ISBuildMenu.cheat off.
- **B18:** missing translations and stale refs:
  - UI_ZeD_Craft_AllStructures and UI_ZeD_Craft_OpenInBuild are in EN only.
  - UI_ZeD_Craft_NeedsSurface and NeedsBench are in EN and DA only, and CC:3100 keeps an English string in code.
  - Search matches the English category word, not the label shown (CC:1125 against CC:976-993).
  - FEATURE_MAP row 249's line refs are stale.
- **B19:** on the pad, with the cursor up and the windows rolled, holding LB then tapping RB (turn left, then right) also zooms (the bumper chord).
- **B20:** an item's "Build" opens the tab with the item's name in the search (STO:33-46), which also matches names, categories and outputs. The game filters by input only (EUI:586-591).
