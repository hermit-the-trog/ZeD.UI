# New game flow: map for the gamut sweep (QA, Nov 27 2026)

A read-only map of the main menu's New game flow as ZeD draws it (the playstyle and challenge pick, the world pick, the spawn town with the save name and seed, sandbox settings and presets, occupation and traits with builds, the character's looks with outfits and the start) against the game's own screens for the same jobs (B42: NewGameScreen, WorldSelect, MapSpawnSelect, SandboxOptionsScreen, CharacterCreationProfession, CharacterCreationMain and, for a new survivor in a running game, CoopCharacterCreation). Written before the sweep scripts. Line refs are as read on Nov 27. Nothing was run.

**The flow is the game's screens with ZeD windows over them.** Every step keeps the game's screen built and hidden as the engine; ZeD's window reads its lists and controls and presses its own buttons (BACK, NEXT, PLAY) through onOptionMouseDown or clickNext / clickBack. The bridge is MM.redirect (MM:2858-2872): a redirected screen's setVisible(true) hides the screen and puts the view on the desk's monitor. New Game is redirected by hand (MM:2847); the rest register with MM.addView and are redirected in the same loop (MM:2850-2852): "world" from worldSelect (WD:322), "spawn" from mapSpawnSelect (SP:791), "sandbox" from sandOptions (SB:765), "traits" from charCreationProfession (TR:650), "looks" from charCreationMain (LK:758). A window hands on with MM.toVanilla (MM:2908-2913: the bottom panel hides) and the screen's own call. There is no Lite branch in any of these files (no Lite or isLite in WD, SB, SP, TR, LK or the New Game part of SV). There is no "players" or split-screen step at the main menu: a second player joins from inside a game, through CoopCharacterCreation, which RSP sends through the same Spawn, Traits and Looks windows. ZeD_MainMenuPlayers.lua is the pause window's Players and Invite pages on a server (PL:3-17), not part of this flow. ZeD_SandboxNotes.lua feeds only the in-game sandbox window (SN:3-5); the new-game Sandbox window does not read it.

Short names: SV ZeD_MainMenuSaves.lua (its New Game part, SV:896-1158), WD ZeD_MainMenuWorld.lua, SP ZeD_MainMenuSpawn.lua, SB ZeD_MainMenuSandbox.lua, TR ZeD_MainMenuTraits.lua, LK ZeD_MainMenuLooks.lua, MM ZeD_MainMenu.lua, OPT ZeD_MainMenuOptions.lua, OMM Overrides/MainMenu.lua, RSP Overrides/Respawn.lua, SN ZeD_SandboxNotes.lua, PL ZeD_MainMenuPlayers.lua, BME ModSupport/BetterModExperience.lua, TIYL ModSupport/ThisIsYourLife.lua, ZUI shared/Translate/EN/UI.json (ZeD's words), FMAP ZeDUI/tools/qa/FEATURE_MAP.md.
The game's files (media/lua/client/OptionScreens unless noted): NGS NewGameScreen.lua, WS WorldSelect.lua, MSS MapSpawnSelect.lua, SO SandboxOptions.lua, SSS ServerSettingsScreen.lua, CCP CharacterCreationProfession.lua, CCM CharacterCreationMain.lua, CMS CoopMapSpawnSelect.lua, CCC CoopCharacterCreation.lua, MS MainScreen.lua, OSK client/ISUI/ISOnScreenKeyboard.lua, CSD shared/Definitions/ClothingSelectionDefinitions.lua.

## 1. What it does

**Getting there:**
- The desk's main menu: New game (MM:1112 in the File menu, MM:2307 in the big buttons, help "New game: start a new game.", ZUI:3865) opens the "newgame" view (MM:997, MM:2921); its window is made once with the desk (MM:1567) and shown by view (MM:1624).
- Every way back to New Game the game has (a challenge's Back, Spawn's Back, the traits screen's Back, the mod list's return, a Lua reset for new-game mods: NGS:536-556) lands on the view through the redirect (MM:2844-2847).
- Safe mode: OMM handBack (OMM:122-163) drops MM.root, so no redirect fires (MM:2865 needs MM.root) and the game's own screens show; takeOver puts the desk back (OMM:165-178).

**Step 1, New game (ZeD_MMNewGame, SV:899-1158):**
- The view: a grid of icons, six to a row (SV:39, 1031), each the game's thumbnail and title (NGS:573-616 for the six playstyles: Apocalypse, Outbreak, Rising, Extinction, Sandbox, Challenges); the row is as tall as the tallest picture (SV:1035-1043). Under it the chosen one's name large and the game's description wrapped (SV:1100-1115; lines that do not fit are dropped, SV:1111). Title "Project Zomboid  +  New game" or "+  Challenges" (SV:1061, ZUI:2082-2083).
- Challenges: Next on the Challenges icon swaps the grid to the challenge list (SV:961-967): ChallengeList (or the older LastStandChallenge), sorted by name (SV:918-919), each { mode, title, desc, thumb, video, challenge } as the game builds it (NGS:220-233). Back from the list returns to the playstyles with Challenges picked (SV:979-984). Coming back from a challenge's character creation reopens the list on that challenge (SV:936-946).
- Controls: a click picks, a second click within 450 ms goes on (SV:1006-1017). The band: Back | Choose mods, Next (primary; grayed with nothing picked) (SV:1117-1122). Hover help "Click a game to choose it, and click it again to go on." (SV:1096, ZUI:3863).
- Next: ng.inChallengesView and ng.selectedItem set, then the game's NewGameScreen.clickPlay (SV:968-974). The game then: setGameMode, setDefaultSandboxVars (resetToDefault and toLua, MS:924-927), the playstyle's preset for a non-Sandbox mode (NGS:418-421), setMap("DEFAULT"), createWorld flag true, then World if WorldSelect has choices, else Spawn (NGS:423-456). A challenge instead runs doChallenge, picks a numbered world name, calls createWorld(worldName) at once, uses the default spawn region and goes straight to occupation and traits (NGS:407-416).
- Better Mod Experience wraps Next with that mod's checks (BME:282-298).
- Back: leaving the list first; else inChallengesView cleared, MainScreen.resetLuaIfNeeded (a Lua reset when new-game mods were changed, MS:1148-1157), the main view (SV:977-991).
- Choose mods: the game's ModSelector for a new game, returning to NewGameScreen (SV:993-1004).
- Keys: Escape is Back, Return is Next, Left and Right step the pick (SV:1149-1156); Up and Down do nothing here (keyOther returns false, MM:3229).
- Pad: the icons are specs by row and column; the D-pad focus is the pick (SV:1131-1136); A Next, Y Choose mods, B Back (SV:1137-1147).

**Step 2, World (ZeD_MMWorld, WD):** shows only when map mods make more than one map group (WS:17-21 hasChoices; vanilla alone never shows it).

- Band: Back | Next (primary; grayed with no world; help "Next: start the new game in the chosen world.", WD:152-154, ZUI:1356).

## 3. Gaps and risks (NG1 to NG64)

Staging: "MM" means a Lua script at the main menu can do it (show the view, set the game's controls, call the window's methods, read the game's objects) without starting a game; pressing Play on Looks (or Return or A there, or Next on a challenge, NG7) is not allowed. "No" says why.

**New game**
- **NG1.** Six playstyles in the game's order with the game's titles and descriptions; Next on each lands on World or Spawn with getWorld():getGameMode() set (SV:956-975, NGS:387-456). Plain check. MM.
- **NG2.** Challenges: the icon opens the list (not Next), Back returns with Challenges picked, the list sorted by name, every challenge's picture sits on its label (SV:961-967, 979-984, 1080-1086). Plain check. MM.
- **NG3.** Back from a challenge's occupation step reopens the challenge list on that challenge (SV:936-946). Plain check. MM (only by calling the traits Back after NG7's Next, so No in practice).
- **NG4.** Many challenges (mods) at 1280x720: the grid's height counts every row (SV:1047-1048) but the window is capped (SV:1057-1060), so rows can run past the description box, which keeps 40 units (SV:1102); no scroll. Bug if rows clip. MM (fake ChallengeList entries).
- **NG5.** Long descriptions are cut at the box with no scroll or "..." (SV:1110-1114). Design call. MM.
- **NG6.** Keyboard Up and Down do nothing in the grid (SV:1150-1156, MM:3229); with seven or more challenges only Left and Right reach the second row. Design call. MM.
- **NG7.** Next on a challenge runs doChallenge and createWorld(worldName) at once (NGS:407-416): see whether a numbered folder appears under Saves/ and whether Back then leaves it. Plain check. No for QA (it may write a save); read only.
- **NG8.** Choose mods then Back: resetLuaIfNeeded resets Lua when new-game mods changed (SV:989, MS:1148-1157) and the menu comes back on the desk (NGS:536-556). Plain check. MM up to the reset; the reset itself No.
- **NG9.** Double-click timing (450 ms) on an icon goes on; a slow second click only re-picks (SV:1006-1017). Plain check. MM.
- **NG10.** Better Mod Experience: with a failing mod check Next stops and says why; on Challenges it does not block the list (BME:282-298). Plain check. No without that mod.
