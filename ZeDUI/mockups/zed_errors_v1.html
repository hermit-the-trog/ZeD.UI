Messages: errors you can read in the game

Messages already counts Lua errors per mod and copies them for a bug report. This turns that into an error manager: each error grouped by mod and by the place it comes from (file and line), how often and when, the message and the call chain in readable form, what it usually means where that can be known, and a Bug report button that builds the whole text for a post. No quitting to read console.txt. The errors are real, from the 128-mod test on 42.21.

Decisions for you

  1. RECOMMENDOne card per place, not per error. A mod's errors are grouped by where they come from: the file and line the game names (BWOScheduler.lua, line 42, in generateSchedule). A repeat counts up on the same card with the first and last time (game time), so a mod that errors every minute is one card that says "17 times, about once a game minute", not 17 cards.
  2. RECOMMENDThe message as the game wrote it, then in plain words. The game's text stays (it is what the mod's maker needs). Under it, a plain reading of the common kinds, only where the wording is certain: attempted index: X of non-table: null means the code looked up X in something that is not there; Object tried to call nil in F means it called a function that does not exist, often a game function this version no longer has. Kinds ZeD does not know get no reading.
  3. RECOMMEND"What this usually means" only from what ZeD knows: the results of ZeD's own compatibility tests (the list in the Workshop's Compatibility thread, shipped with ZeD), and the mod's own game version range from its mod.info. Nothing guessed. A mod not in the list gets the plain reading only.
  4. RECOMMENDBug report builds the text for a post: ZeD-GUI's version, the game's version, the mods that are on in load order (name, id, Workshop id), files turned off or picked, and the error with its count, times, message and full call chain. Copy puts it on the clipboard; Save writes it to Zomboid/Lua/ZeD_bugreport_<date>.txt. Open its page takes you to the mod's Workshop page in the Steam overlay.
  5. RECOMMENDOpen in Mods goes to the Files tab at the file the error names (the file switches mockup). From a game it opens the pause window's Mods; changes to a mod's files take effect the next time the save loads.
  6. LIMITconsole.txt cannot be read by a mod (the game lets mods read files in Zomboid/Lua only). The report says where it is and asks to attach it: C:\Users\(you)\Zomboid\console.txt, copied before restarting.
  7. LIMITLua errors only. The game's own Java errors (a broken map cell, a missing model bone) go to console.txt but not to the list mods can read. The game keeps the last 40 error lines; Messages reads them every 2 seconds, so it keeps up; every error is counted, and the last 12 of each place are kept in full (as Messages keeps 12 per mod today).
  8. YOUR CALLErrors from before the game started (while mods and the world load, like Ladders!? here) are left to console.txt today. Recommend: show them too, marked "while loading".
  9. YOUR CALLMessages at the main menu. Today it lives in the game. Errors at the main menu (a mod's options page, the desk) could show in a Messages window on the desk as well.
  10. FOUNDA mod name with brackets is cut short today: "Ladders!? (v0.0.13)" is filed as "Ladders!? (v0.0.13" because the name is read up to the first closing bracket. The error manager reads it to the double bracket that ends it.
  11. Controller: as Messages today: the list, the cards and the footer are zones; A presses a card's buttons; in the report, A on Copy, B back.
