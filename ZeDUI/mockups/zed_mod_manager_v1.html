Mod Manager

What you asked for, on the monitor: conflicts found (not only the ones authors declare), Workshop state for every subscribed mod, reload without exiting and a plain reason when a full restart is the only way, an upload screen for your own mods, and a description editor with real layout tools and a live Steam preview. The Mods screen keeps everything it does today (tabs, Find, problem flags, load and map order, profiles); the new parts are added to it. Mod names here are made up.

Decisions for you

  1. RECOMMENDConflicts the game would never tell you about. ZeD reads each mod's files and scripts: two mods shipping the same file (the one that loads later silently replaces the other), two mods defining the same item or recipe, a mod that needs another to load first. Each says in plain words who wins and why, with the fix one press away (move it in the load order, turn one off). Declared clashes, missing requirements and game version stay as they are today. A new Conflicts tab, and the count on each row.
  2. RECOMMENDWorkshop state on every subscribed mod: up to date, update waiting, downloading (with progress), subscribed but not installed, plus when it was last updated and its size. A Workshop tab lists everything you subscribe to, collections grouped. "Open in Steam" on each.
  3. LIMITSteam does the downloading. The game does not let a mod start a Workshop download or subscribe to an item (the Steam functions for that are closed to mods; checked on 42.21.0). ZeD shows what Steam is doing and opens the item's Steam page; when Steam finishes, the reload below picks it up.
  4. RECOMMENDThe bottom strip says what your changes need, before you leave the screen: "Reload" (vanilla's own Lua reload, the one it already runs when you accept a mod change: no exit, seconds) or "Restart needed", with the reason in a sentence naming the mod and the kind of file ("Tanks of Kentucky changed its textures; the game reads textures once, at start"). Which kinds of file truly need a restart gets tested in game before the messages are written.
  5. RECOMMENDAn upload screen for your own mods, on the game's own Workshop functions: your mod folders from the Workshop folder, title, visibility, tags, the preview picture checked against Steam's rules before you upload (not after), what will go up (files, size, mod.info found), the change note, and Upload with a progress bar. New items get created; existing ones updated.
  6. RECOMMENDThe description editor writes Steam's own formatting (Steam descriptions are plain text with formatting codes). You build with blocks: heading, text, list, numbered list, picture, quote, code, table, divider, link, spoiler; drag to reorder; bold, italic, underline, strike and links inside text. A live preview shows it the way Steam will; "Steam codes" shows the raw text to paste anywhere. Starting sections for what readers look for: Features, Requirements, Load order, Compatibility, Known issues, Changelog, Credits. A counter against Steam's 8,000 characters. Change notes use the same editor.
  7. YOUR CALLWhere the upload screen lives. Shown here behind the main window's Workshop button (vanilla's spot). It could also be a desktop icon of its own ("Workshop").
  8. Controller: every list, tab and button is a stop like today; the editor's blocks move with the D-pad and a held A to drag; text goes through the ZeD keyboard.
